# payment-request

Форма запиту на оплату для контрагентів (Telegram Mini App) → рядок у листі «Запити» реєстру запланованих платежів.

| Папка | Що це | Де живе |
|---|---|---|
| `web/` | Екран анкети | GitHub Pages: `https://dv-coo.github.io/payment-request/` |
| `apps-script/` | Приймач | Google Apps Script, веб-застосунок. Тут — копія коду для історії |

Секретів у репозиторії немає: токен бота й ID таблиці — тільки у властивостях скрипта.

## Статус

- [x] Етап 1 — приймач пише рядок у таблицю (тестові дані)
- [ ] Етап 2 — курс НБУ і формула «Сума в ₴»
- [ ] Етап 3 — екран анкети + перевірка підпису Телеграма
- [ ] Етап 4 — сповіщення, ліміт 5/год, лист «Лог»

## Перевірка етапу 1 (на копії реєстру)

1. Реєстр → «Файл → Створити копію». Назвати, напр., «Реєстр — ТЕСТ». Відкрити копію, з адресного рядка взяти ID: частина між `/d/` і `/edit`.
2. https://script.google.com → «Новий проєкт». Назва: «Приймач запитів на оплату».
3. Вставити вміст `apps-script/Code.gs` у файл `Code.gs`. Увімкнути показ маніфесту («Налаштування проєкту» → «Показувати файл appsscript.json») і вставити `apps-script/appsscript.json`.
4. «Налаштування проєкту» → «Властивості скрипта» → додати `SHEET_ID` = ID копії.
5. У редакторі вибрати функцію `testStage1_appendRow` → «Виконати» → дозволити доступ.
6. Перевірити в копії, лист «Запити»: новий рядок, код `R-РРММДД-01`, колонки на місцях, «Сума в ₴» — формула (= 1500,5 × 41,5), Статус / Хто проводить / Рахунок / Категорія / Проєкт — порожні.
7. Запустити `testStage1_rejectsIncomplete` — у журналі «OK, відхилено…», у таблиці нового рядка немає.
8. Ще раз `testStage1_appendRow` — код має стати `…-02`.
