# payment-request

Форма запиту на оплату для контрагентів (Telegram Mini App) → рядок у листі «Запити» реєстру запланованих платежів + сповіщення бухгалтерам у бот.

| Папка | Що це | Де живе |
|---|---|---|
| `docs/` | Екран анкети | GitHub Pages: `https://dv-coo.github.io/payment-request/` |
| `apps-script/` | Приймач | Google Apps Script, веб-застосунок (тут — копія коду) |

Секретів у репозиторії немає: токен бота й ID таблиці — тільки у властивостях скрипта.

## Що вміє

- Анкета з 6 полів; «Надіслати» неактивна, доки не заповнено все. Ім'я підставляється з Телеграма.
- Приймач перевіряє підпис Телеграма (нік не підробити), ліміт 5 запитів/год на акаунт, білий список (вимкнений).
- Рядок у «Запити»: код `R-РРММДД-NN`, курс НБУ на день подання (USDT = USD, UAH = 1, вихідні — останній установлений), «Сума в ₴» — формулою. Статус / Хто проводить / Рахунок / Категорія / Проєкт — порожні.
- НБУ недоступний → курс порожній, запит проходить, у сповіщенні позначка.
- Велика кнопка «📝 Запит на оплату» на всю ширину внизу чату (постійна клавіатура; анкета з неї шле дані через Телеграм — `sendData`, бот обробляє у вебхуку). Кнопка «Відкрити» у списку чатів — Main Mini App у BotFather (адресу анкети друкує `setup`).
- Повтор доставки від Телеграма не створює другий рядок: позначки оброблених оновлень лежать у властивостях скрипта (кеш Apps Script живе лише кілька годин), старі прибирає `pruneSeenUpdates_`. Та сама анкета двічі протягом 10 хв теж не дублюється.
- Бот не для листування: опис до «Start» і інструкція з кнопкою «📝 Подати запит» після «Start»; будь-яке інше повідомлення в чаті видаляється, бот нагадує про кнопку (не частіше разу на 10 хв). Список команд прибрано.
- Довідники з FinMap щодня о 8:00 (прихований аркуш «Довідники»): категорії, рахунки, проєкти, контрагенти — без системних і `[Архів]`. Спадні меню в колонках «Категорія», «Рахунок списання», «Проєкт», «Контрагент» (ввести вручну теж можна — буде лише попередження). «Статус» і «Хто проводить» — копія меню з рядка 2 на весь стовпець.
- «Контрагент (як у FM)» — найближче ім'я з довідника FinMap (порядок слів, укр/рос написання, ФОП, по батькові, ініціали, зменшувальні імена, одруківки). Немає надійного збігу — клітинка порожня, у сповіщенні позначка. Ім'я як написала людина + клікабельне посилання `https://t.me/нік` на чат з нею — у «Контакти контрагента».
- «Проєкт» у нових запитах — «Вища Ліга 6.0» (властивість `DEFAULT_PROJECT`), у меню можна змінити. У меню лише активні проєкти: завершені, що не позначені `[Архів]` у FinMap, перелічені в `HIDDEN_PROJECTS` у коді.
- Сповіщення про новий запит вам, підтвердження контрагенту з кодом.
- Лист «Історія змін» (кожне звернення), щоденний моніторинг о 9:00 (спроби були, а жодна не пройшла → повідомлення адміну), щомісячна копія реєстру в папку «Архів реєстру платежів».

## Запуск — один раз (≈15 хв)

1. **GitHub Pages.** Репозиторій → Settings → Pages → Source: *Deploy from a branch*, Branch: `main`, папка `/docs` → Save.
2. **Скрипт.** Відкрити реєстр → «Розширення → Apps Script». Вставити `apps-script/Code.gs` у `Code.gs`. «Налаштування проєкту» → увімкнути «Показувати файл appsscript.json» → вставити `apps-script/appsscript.json`. Зберегти.
3. **Властивості скрипта** («Налаштування проєкту» → «Властивості скрипта»):
   - `SHEET_ID` — ID реєстру `1lRS7blAUK0zUHywtz7AHhJZoT9VFX4rllC0NvczOj-Q`
   - `BOT_TOKEN` — токен бота
   - `FINMAP_TOKEN` — ключ API FinMap
   - `ADMIN_CHAT_ID` — ваш Telegram ID (дізнатися в @userinfobot). Сюди йдуть сповіщення про запити й моніторинг.

   Необов'язково: `NOTIFY_CHAT_IDS` — ID інших людей через кому, якщо сповіщення треба комусь ще (кожен має натиснути «Start» у боті).
4. **Публікація.** «Розгорнути → Нове розгортання» → тип «Веб-застосунок» → Виконувати від імені: *я*, Доступ: *Усі* → Розгорнути → дозволити доступ.
5. **Налаштування.** У редакторі вибрати функцію `setup` → «Виконати». Вона перевіряє колонки, створює «Історія змін», налаштовує бота (опис, кнопка меню «Запит на оплату», вебхук), вмикає моніторинг і бекап. Ви отримаєте «✅ Приймач … підключено» — це і є перевірка зв'язку.
6. **Реєстр.** Прибрати «Вища Ліга 6.0» з рядка 2 листа «Запити». У лист «Правила» додати:
   > Реквізити із запиту через форму звіряти з відомими реквізитами контрагента до оплати. Нові або змінені реквізити — підтвердити в контрагента іншим каналом.

Перший реальний запит через бот — і є фінальна перевірка: рядок у «Запити», сповіщення вам.

## Налаштування потім

- Замінили бота (новий `BOT_TOKEN`) або змінили код → «Розгорнути → Керування розгортаннями» → ✏️ → «Нова версія» → «Розгорнути», потім знову запустити `setup`.

- Білий список: `WHITELIST_ENABLED` = `true`, `WHITELIST_IDS` = ID через кому.
- Ліміт: `RATE_LIMIT_PER_HOUR`.
- Змінили код скрипта → «Розгорнути → Керування розгортаннями» → редагувати → «Нова версія». Адреса не зміниться.
- Якщо `setup` скаже, що не визначив адресу, — додати `WEBAPP_URL` (адреса розгортання, закінчується на `/exec`) і запустити ще раз.
